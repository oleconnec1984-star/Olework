# OLE WORK

Private, owner-operated employee and task workspace, built with React/Vinext and a Sites D1 database.

## Connected product flows

- Employee IDs connect assignments, reviewer queues, editable avatars, calendar due dates and reports.
- Task lifecycle: pending → working → review → complete; reviewers can return work with a reason.
- Checklists must be complete before review/approval. Completion time is set at approval.
- Important calendar events have editable titles, dates, times and colors.
- Reports derive all counts and percentages from stored tasks. Report drilldowns retain filters.
- Dates use Asia/Bangkok. Branch/department reports use employees' **current** organization, not historical snapshots.

## Persistence and identity

The dispatch-provided stable user ID owns one row in `ole_workspaces`. All API operations require that identity; the Site access policy controls who can visit. Employee records are **not** sign-in accounts. The current publication is a private administrator workspace, not a shared employee portal.

Each save uses an atomic revision comparison. Conflicting saves return HTTP 409 and keep the caller's draft for manual reconciliation; no silent overwrites. SQL migration files are generated by Drizzle and applied by Sites deployment, not request handlers.

Browser storage contains only display preferences and legacy data left by the old prototype. Legacy import is explicit, validated and non-destructive to the original browser data. Old in-memory tasks cannot be recovered after closing that old page. Sample data is opt-in and visibly labelled, never presented as actual performance.

There is no LINE delivery, Google Calendar synchronization, file attachment service, or employee-role authentication. The UI discloses these limitations without fake connection buttons.

## Verification

- `npm test`: model and API regressions against a local D1 database, including identity, read/write, revision conflicts, invalid references, workflow gates, Bangkok dates and metrics.
- `npm run test:render`: bounded local test of the built Worker, server-rendered Thai shell and data route; requires a successful build.
- `npx tsc --noEmit`: type check. Runtime declarations in `worker-configuration.d.ts` were generated by Wrangler from the built binding configuration.
- `npm run db:generate`: generate migrations after schema edits.

These tests do not automate user clicks or substitute for browser/visual QA.
